# 安全边界

## M1 信任模型

当前前端使用 Clerk 登录控制复盘工作台入口；固定访客用户仍仅用于后端数据模型隔离，不是服务端认证机制。因此：

- 未登录用户只能停留在项目库，不能创建、打开或恢复复盘视图。
- 前端 guard 不保护 API；生产若可从互联网访问，必须在 Nginx 上游使用 VPN、IP 白名单或成熟的身份代理。
- 回测 API 仍使用固定访客用户，不能把 Clerk 前端状态误认为服务端身份校验。

## 网络

- 只有 Nginx 映射宿主机端口。
- PostgreSQL、行情服务和回测服务只加入私有 Compose 网络。
- Nginx 根据固定路径代理，不接受客户端提供的任意上游地址。
- 内部服务不信任 `X-Forwarded-*` 的客户端原值；Nginx 覆盖相关头。

## 输入与资源限制

- Axum 对所有数值、枚举、名称长度和时间范围执行服务端校验。
- Nginx 限制请求体大小；M1 JSON API 建议 `1m`。
- 单次行情/回测最多 5,000 根聚合 K 线，防止过量 CPU 与响应体。
- 数据库只使用参数化 SQL；错误响应不返回 SQL、路径或堆栈。
- Parquet 路径由环境配置，不能由 API 请求指定。

## 容器与密钥

- Rust 运行镜像使用非 root 用户和只读根文件系统；只给必要临时目录写权限。
- 行情目录与 TLS 私钥只读挂载。
- PostgreSQL 密码、证书私钥和备份密钥不得提交到 Git 或写入镜像。
- 依赖镜像固定主版本并定期扫描；发布前检查 Rust 与 npm 依赖漏洞。

## 浏览器安全

- 默认同源访问，不在生产启用宽泛 CORS。
- CSP 默认限制本站资源；为 Clerk 放行已配置的 Frontend API、保护域、Cloudflare challenge 和图片域；样式允许本站文件和 inline style，以支持图表库运行时设置尺寸与颜色；不使用未列入 allowlist 的运行时 CDN。
- 使用 HSTS、`nosniff`、受限 Referrer Policy 和合理的 Permissions Policy。
- Vue 不渲染来自 API 的未转义 HTML。

## 服务端认证边界

当前 Clerk 登录只在前端保护复盘界面。若要保护 API 或实现多用户数据隔离，服务端必须从经过验证的身份声明映射 `user_id`，所有列表和详情查询继续按 `user_id` 过滤。不得把固定访客数据自动归属给首个注册用户；迁移必须显式确认。
