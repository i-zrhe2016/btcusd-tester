# 安全边界

## 身份与用户数据隔离

复盘工作台与回测/配置/项目 API 都要求 Clerk 登录：

- 前端门禁只负责界面入口；真正的身份校验在服务端。回测服务和支付服务都验证 RS256 JWT 的签名、issuer、有效期和 `azp`，并把经过校验的 `sub` 映射为 `users.id`。
- 所有用户数据查询（`backtests`、`strategy_configs`、`replay_projects`、支付订单）都带 `user_id` / `clerk_subject` 条件；详情接口对不属于当前用户的记录统一返回 404 或空结果。
- 浏览器 `localStorage` 既不是身份凭据，也不是跨用户共享区：所有用户键都以 Clerk `sub` 加命名空间（`…u.user_xxx`）。旧版未区分账户的本地项目只能通过显式确认导入当前账户或删除，不会自动归属给首个登录用户。
- 支付状态查询按订单和 Clerk `sub` 联合过滤，不能通过订单 ID 读取其他用户的支付结果。

## 网络

- 只有 Nginx 映射宿主机端口。
- PostgreSQL、行情服务和回测服务只加入私有 Compose 网络。
- Nginx 根据固定路径代理，不接受客户端提供的任意上游地址。
- 内部服务不信任 `X-Forwarded-*` 的客户端原值；Nginx 覆盖相关头。

## 输入与资源限制

- Axum 对所有数值、枚举、名称长度和时间范围执行服务端校验。
- Nginx 限制请求体大小；M1 JSON API 建议 `1m`。
- 单次行情/回测最多 5,000 根聚合 K 线，防止过量 CPU 与响应体。
- 数据库只使用参数化 SQL；错误响应不返回 SQL、路径或堆栈。
- Parquet 路径由环境配置，不能由 API 请求指定。

## 容器与密钥

- Rust 运行镜像使用非 root 用户和只读根文件系统；只给必要临时目录写权限。
- 行情目录与 TLS 私钥只读挂载。
- PostgreSQL 密码、证书私钥和备份密钥不得提交到 Git 或写入镜像。
- 依赖镜像固定主版本并定期扫描；发布前检查 Rust 与 npm 依赖漏洞。

## 浏览器安全

- 默认同源访问，不在生产启用宽泛 CORS。
- CSP 默认只允许本站资源（样式额外允许 inline style，以支持图表库运行时设置尺寸与颜色）；不使用未列入 allowlist 的运行时 CDN。
- 使用 HSTS、`nosniff`、受限 Referrer Policy 和合理的 Permissions Policy。
- Vue 不渲染来自 API 的未转义 HTML。

## 迁移与遗留数据

不得把固定访客数据或旧版共享浏览器数据自动归属给首个注册用户；迁移必须显式确认。`replay_projects` 从旧 `localStorage` 导入时由用户在对话框中二选一：导入当前账户，或从浏览器删除。导入失败时旧数据保留在本机，不会静默丢弃。
