## Implemented

- Vue/Vite 复盘工作台支持 K 线播放、手动交易和 CandleKit 提供的 TradingView 风格绘图工具。
- 复盘控制栏提供 Buy、Sell 和仅在持仓时启用的显式平仓按钮；平多/平空按当前持仓数量生成交易记录并复用既有盈亏计算。
- 主屏 K 线的手动交易标记区分开仓与平仓并带单笔序号：白色 `BUY #n` / `SELL #n` 表示开仓，琥珀色 `平多 #n` / `平空 #n` 表示平仓，序号按项目内交易时间顺序从 1 开始。
- 图表顶部预留 32px 控件条承载 Stoch 参数入口（展开时才覆盖绘图区），并加大价格轴上下留白，交易标记及其文字不再被图例或画布边缘遮挡。
- 左侧分组工具栏支持 16 个绘图工具、选择/拖动、锁定、删除、清除和 Shift 测量。
- 绘图以通用 `drawings` 模型与复盘项目一起保存在 `btcusd.replay.projects.v2`；v1 旧趋势线升级时清空但保留 v1 原始数据。
- 图表保持黑白 K 线、无成交量副图；Stoch 副图以已播放收盘价计算 K/D，可在两组（四条曲线）与三组（六条曲线）间切换，不再绘制固定 20/50/80 参考线，按周期设置参数、恢复默认并在浏览器保存。
- 图表关闭 Lightweight Charts 的 TradingView 图标，改在页面底部提供 TradingView 署名与链接（库许可证要求二选一）。
- 图表支持右键菜单清除当前项目的全部绘图。
- 行情聚合与复盘周期支持 1m、5m、15m、30m、1h、2h、3h、4h、1d、1w、1M；Stoch 使用用户提供的各周期 K1/K2 默认值，K3 取桌面端第三组默认值并使用户保存的两参数数组按两组解析。
- 图表为底部状态栏预留高度，窄屏及全屏下副图与时间轴不被遮挡；CandleKit 私有存储关闭，绘图使用应用项目状态。
- 复盘行情首次加载、切换周期和恢复项目都以游标为锚点取「之前 500 根历史 + 之后 30 根」（单次上限 531 根，接口硬上限 5,000 根），窗口允许读到项目 `from` 之前的历史作为图表上下文；播放时按每批 60 根预取后续窗口，当前批次剩余 15 根未播放时后台加载，窗口末尾等待加载结果，失败暂停并支持手动重试。
- 新行情窗口按 timestamp 去重、排序后追加，过期、重复和无进展请求不会覆盖当前复盘数据。
- 复盘状态栏支持播放中调整 `0.25x`–`8x` 速度，调整后即时重建播放定时器并持久化当前项目速度。
- 复盘页支持 `A` 播放/暂停、`B` Buy、`S` Sell、`C` 启用趋势线快捷键；输入控件、组合键和长按重复不会触发。
- 复盘切换周期保留手动交易与绘图：交易按 `timestamp` 重新锚定到新周期包含该时间点的 K 线，绘图保持原始时间/价格；持仓与盈亏连续。
- 复盘页支持 1–4 屏多周期分屏：状态栏控制屏数，每个屏幕顶部使用同一套周期切换条（屏标识 + 周期选择，副屏另有移除按钮），各屏共享复盘游标时间并随播放/暂停/主周期切换保持时间对齐。
- 复盘时钟取游标所在 K 线的收盘时刻；每屏只渲染该时刻之前已收盘的 K 线，并补上仍在形成的那根：已收盘部分用该屏窗口数据，形成中的那根按当前时钟单独聚合（`limit=1`，桶取包含最后一个已播放时刻的该屏周期桶），因此副屏既不会提前显示未播放行情，也不会落后一个周期；时钟正好落在该屏周期网格上时直接使用窗口内已收盘 K 线，不额外请求（主屏周期更粗时不产生额外请求）。形成中取数失败时保留上一次渲染结果。
- 每屏周期切换条都列出行情元数据支持的全部周期（含 30m）；选择其他屏正在使用的周期会互换两屏周期（涉及主屏时同步切换项目主周期并保留复盘进度），因此不存在不可选的周期或被静默忽略的选择。
- 每个副屏按自己的周期以游标为锚点取「之前 500 根 + 之后 500 根」窗口（上限 1001 根），游标越出已加载范围时按游标重新取窗口，失败只在对应屏内提示和重试；交易、绘图和绘图工具栏仍只作用于主屏。
- 分屏配置以 `panes` 字段随项目保存在 `btcusd.replay.projects.v2`，旧项目按单屏加载，主周期始终是 `panes[0]`，最多 4 屏。
- 当前已加载/已播放 K 线右侧追加一批 Lightweight Charts whitespace 时间槽，不绘制虚假 K 线但支持 CandleKit 在未加载时间区域创建绘图锚点；行情追加或播放推进后按时间戳保留绘图。
- Replay 顶栏压缩为 48px，统一展示项目、周期、播放状态、进度和仓位；项目库入口与全屏入口收进顶栏。
- Replay 底部控制栏压缩为 56px，集中周期、播放速度、播放/交易、当前时间、加载更多和全屏操作；窄屏自动换行。
- 图表可视范围按播放数据量调整 K 线间距，把最新已播放 K 线贴近右侧（约 6% 留白），其余宽度尽量铺满游标之前的历史 K 线；只有项目起点早于行情数据起点时才在左侧保留无法填充的空白。
- CandleKit 工具栏改为单列 40px；沉浸式全屏隐藏网站顶栏、保留底栏，并通过左侧边缘热区按需显示工具栏。
- Nginx 作为公网入口，行情和回测服务运行在私有网络中。

## Constraints

- 浏览器通过同源 `/api/...` 访问服务；本地 Vite 优先连接 `127.0.0.1:8081/8082`，否则回退到 HTTPS 网关。
- 部署使用 Tailscale 内网地址；后端仍使用固定访客用户，未完成服务端 Clerk 身份校验。
- CandleKit 版本固定为 `@getcandlekit/charts@0.1.0`；绘图持久化由应用项目模型负责，不使用 CandleKit 私有 localStorage。
- Lightweight Charts 固定为 `lightweight-charts@5.2.1`，关闭 `attributionLogo` 时必须保留页脚署名链接。
- 该 Tailscale 节点不得再配置监听 443 的 `tailscale serve`：它会劫持内网 HTTPS 且节点未启用 Tailscale 证书，导致按节点内网地址访问 HTTPS 时无法打开。
- Windows 桌面端源码（原 `legacy/windows-desktop/`）、构建工作流和迁移文档已移除，仅保留在 Git 历史中；新功能不再对照 C++ 实现验收。

## Architecture Snapshot

- `frontend/` 提供 Vue/Vite 单页工作台；`MarketChart.vue` 以 CandleKit `ChartController`、`DrawingEngine`、`DrawingController` 和 `MeasurementController` 组合 Lightweight Charts；Rust `market-data` 和 `backtest` 服务提供行情与回测 API；Nginx 负责边缘入口。
- 详细边界见 `docs/architecture/service-boundaries.md`，前端行为见 `docs/frontend/web-app.md`。
