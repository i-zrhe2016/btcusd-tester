# 关键架构决策

本文记录已经锁定的决策。变更决策时应在本文件追加替代说明和日期，而不是只修改实现。

## ADR-001：两个业务服务起步

**决定**：M1 仅使用 `market-data` 和 `backtest` 两个 Axum 服务。

**原因**：行情计算与用户回测的状态模型、资源特征和数据所有权不同，拆开能保持单一职责；继续拆出用户、指标或结果服务会增加网络调用而没有独立扩缩容价值。

## ADR-002：Parquet 是行情事实来源

**决定**：历史 OHLCV 只保存在 Parquet，PostgreSQL 不复制行情。

**原因**：列式文件适合时间范围扫描、压缩和离线替换；避免将百万级不可变行情变成数据库运维负担。

## ADR-003：服务端计算指标

**决定**：K 线聚合和 Stoch 均由行情服务计算；前端只展示。

**原因**：浏览器与回测使用同一结果，避免 TypeScript/Rust 两份算法产生信号偏差。

## ADR-004：同步回测 API

**决定**：M1 的 `POST /api/backtests` 同步等待完成，同时在数据库维护状态。

**原因**：单次最多 5,000 根聚合 K 线，预计在普通单机上能快速完成，无需消息队列。若实测超过 Nginx 60 秒超时或出现并发排队，再引入异步作业模型；API 的记录状态已为该升级预留。

## ADR-005：单机访客模式

**决定**：M1 不实现登录，所有请求使用固定访客用户。

**原因**：目标先是单机研究工具。未启用认证前不得把应用直接暴露给不受信任的公网用户，生产部署必须使用 VPN、IP 白名单或上游认证保护。

## ADR-006：HTTPS 在 Nginx 终止

**决定**：TLS 仅在 Nginx 终止，内部 Compose 网络使用 HTTP。

**原因**：单机内部链路不离开 Docker bridge；集中管理证书更简单。开发环境允许自签名证书，生产必须挂载受信任证书。

## ADR-007：渐进迁移旧客户端（已取代，2026-09-13）

**决定**：M1 与旧 Windows 客户端并行，M2 达到功能等价后再停止旧客户端维护。

**原因**：回放、绘图和多窗口联动与基础回测不是同一个交付风险，分期可以验证服务架构而不丢失现有能力。

**取代说明（2026-09-13）**：Windows 桌面端源码、构建工作流和迁移文档已移除，Web 平台不再保留 C++ 客户端作为并行交付物。历史行为基准只保留在 Git 历史中，不再作为可构建的对照实现。

## ADR-008：复盘界面需要登录（2026-09-06，已被 ADR-010 取代）

**决定**：前端使用 Clerk 会话状态保护复盘视图入口。未登录用户只能停留在项目库，不能创建、保存、选择或从本地状态恢复复盘项目；登录后才允许进入复盘。

**原因**：复盘界面包含项目状态和手动交易操作，需要明确的用户入口控制；使用现有 Clerk 集成即可完成最小改动，不新增认证服务。

**边界**：本决定只改变前端界面访问控制，不改变行情和回测 API 的当前固定访客用户边界。若后续需要真正的多用户数据隔离，必须单独实现服务端会话校验和 `user_id` 映射。该决定取代 ADR-005 中“前端不实现登录”的部分，ADR-005 关于后端访客数据模型的部分继续有效。

## ADR-009：绘图能力迁移到 CandleKit（2026-09-08）

**决定**：复盘图表使用固定版本 `@getcandlekit/charts@0.1.0` 提供绘图引擎、绘图控制器和 Shift 测量交互；应用继续使用 Lightweight Charts 的底层图表和交易标记能力。支持 CandleKit 已发布的 16 个绘图工具，不引入文本或自由手绘工具。

**原因**：现成框架已经覆盖 TradingView 风格的锚点、选中、拖动、锁定、删除和测量行为，能够减少自维护的画布交互代码，同时保持当前黑白 K 线、手动交易和回放模型不变。

**持久化边界**：CandleKit 的 `storageKey` 关闭，项目级 `drawings` 是唯一来源，由应用写入 `btcusd.replay.projects.v2`。v1 项目继续可读，交易和游标保留，旧自定义趋势线按升级时清空策略不迁移；后续保存写入 v2。

## ADR-010：移除 Clerk 登录集成（2026-09-13）

**决定**：卸载 `@clerk/vue`，删除登录、注册与账户 UI、前端会话 guard、`VITE_CLERK_PUBLISHABLE_KEY` 构建参数，以及 nginx CSP 中为 Clerk 和 Cloudflare challenge 放行的域名。项目库与复盘视图对所有访问者直接可用。

**原因**：认证开关关闭时该集成不产生运行时行为，只留下未启用的界面代码、构建期密钥依赖和额外的 CSP 放行面；移除后前端构建不再依赖任何 Clerk 配置。

**边界**：本次只做前端与构建链清理，不改变后端固定访客用户与 `user_id` 数据模型。该决定取代 ADR-008；若将来需要多用户隔离，必须按 ADR-005/ADR-008 的边界单独实现服务端会话校验和 `user_id` 映射。

## ADR-011：复盘项目按用户存储（2026-11-04）

**决定**：在回测服务中新增 `replay_projects` 表与 `/api/projects` 接口（`GET` 列表、`PUT /{id}` 幂等写入、`DELETE /{id}`），所有查询以 Clerk 认证映射的 `user_id` 过滤。前端仍保留 `localStorage` 作为离线缓存，但所有用户键以 Clerk `sub` 命名空间隔离；升级前未区分账户的本地项目必须由用户显式选择导入或删除。

**原因**：Clerk 登录恢复后，后端回测、配置和支付已按用户隔离，唯独复盘项目仍只存在于共享的浏览器存储：同一浏览器切换账户会互相看到项目，换设备则完全丢失。把项目提升为服务端数据既完成多用户隔离，也让复盘工作台具备跨设备持续性。

**边界**：游标高频更新在客户端合并为低频 PUT，并在暂停、切换项目、页面隐藏或卸载时补发；服务端不可用时继续使用该用户的本地缓存。该决定取代 ADR-010 末尾“若将来需要多用户隔离”的待办，并修订 `docs/database/schema.md` 中“回放状态由未来 replay 服务拥有”的说明。

## ADR-012：图表指标在浏览器端计算（2026-11-05）

**决定**：复盘图表新增的经典指标库（SMA、EMA、WMA、VWAP、BOLL、RSI、MACD、ATR、KDJ、OBV、CCI、WR、DMI、ROC、TRIX）由前端 `@getcandlekit/charts` 的 `IndicatorRegistry` + `IndicatorController` 基于已播放 K 线计算并绘制；选择与参数按周期存入复盘项目的 `indicators` 字段，服务端只做结构校验，不维护指标目录白名单。

**原因**：这些指标只服务于复盘图表的可视展示，随播放游标逐根重算，数据量小且无需持久化中间结果；放在浏览器端可避免为每个播放 tick 增加一次服务端往返，也让图表交互（开关、改参数）即时生效。复用 CandleKit 现有引擎可以避免维护第二套指标实现。现有 Stoch 副图一直由前端计算，本决定与该既有行为保持一致。

**边界**：本决定修订 ADR-003“服务端计算指标”的范围——**回测信号**仍由服务端计算，以保证结果可复现和可审计；浏览器端指标只用于展示，不作为交易或回测决策的权威来源。服务端校验只检查结构（周期键、数量、名称长度、参数类型与有限性），未知指标名由客户端丢弃，因此前端新增指标无需后端发布。指标目录与参数在 `frontend/src/indicators.ts` 维护，类型与结构规范化在无图表依赖的 `frontend/src/indicatorModel.ts`。
